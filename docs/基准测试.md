# 基准测试（bench 子命令）

`UEToVS.Engine bench` 在真实的 UE 项目上量化 UEToVS 引擎的速度、内存和结果质量，用来比较版本之间的变化、定位性能回退。它和 VS 里运行的是同一个引擎、同一份索引，但不需要启动 VS。

## 做什么

1. **索引**：默认复用磁盘上已有的索引（`<解决方案>\.vs\UEToVS\` 下，和 VS 里打开时的同一份），只增量处理变动的文件；加 `--reindex` 时删掉 C++ 索引从头重建。记录索引耗时、文件数、符号数。
2. **取样**：从项目的 `.h` / `.cpp` 中随机取 N 个标识符位置（默认 1000 个）。随机数由 `--seed` 决定，**同一份索引 + 同一个 seed = 同一批位置**，所以两次运行可以直接对比。默认只取项目代码，加 `--all` 也从引擎代码取样。
3. **计时**：在每个位置依次执行
   - `completion`：补全（模拟已经敲了标识符的前一半）；
   - `definition`：转到定义；
   - `references`：查找引用。
4. **报告**：每种操作的 p50 / p95 / p99 / 平均 / 最大耗时（毫秒）、**空结果比例**（没有结果或出错的位置占比）、进程峰值工作集 / 峰值私有内存 / 托管堆大小、索引耗时。
5. **记录与对比**：结果追加为一行 JSON 写入 `<解决方案>\.vs\UEToVS\bench\bench.jsonl`，并和同一项目的**上一次**结果对比，在终端打印变化百分比。

## 用法

```bat
UEToVS.Engine.exe bench --project D:\Work\MyGame\MyGame.uproject
```

从源码运行：

```bash
dotnet run --project src/UEToVS.Engine -c Release -- bench --project D:\Work\MyGame\MyGame.uproject
```

`UEToVS.Engine.exe` 随扩展一起安装，位于 VSIX 安装目录的引擎子目录下。

### 参数

| 参数 | 说明 |
| --- | --- |
| `bench` | 必须是第一个参数 |
| `--project <x.uproject>` | 要测的项目（默认：解决方案目录或其上级目录中的第一个 `.uproject`） |
| `--solution-dir <dir>` | `.sln` 所在目录，决定索引和结果放在哪个 `.vs\UEToVS` 下（默认：项目目录） |
| `--samples <n>` | 取样位置数，默认 1000 |
| `--seed <n>` | 随机种子，默认 1 |
| `--ops <列表>` | 只测其中几项：`completion,definition,references`（逗号分隔） |
| `--reindex` | 删除 C++ 索引后重建（测完整索引时间）；默认复用已有索引 |
| `--all` | 也从引擎 / 第三方代码中取样 |
| `--details` | 另外把每个位置每项操作的耗时写入 `bench-<时间>-samples.jsonl`，便于找出最慢的位置 |
| `--out <dir>` | 结果目录（默认 `<解决方案>\.vs\UEToVS\bench`） |
| `--no-compare` | 不和上一次结果对比 |
| `--skip-engine` | 只索引项目代码（引擎代码不进索引，补全和跳转会少很多结果） |
| `--no-watch` | 不监视文件变化（bench 一般都可以加上） |

其余引擎参数（`--cpp-threads`、`--engine` 等）和服务器模式相同，见 `UEToVS.Engine --help`。

## 输出示例

```
project:  D:\Work\MyGame\MyGame.uproject
samples:  1000 (seed 1)   previous: 2026-11-10 21:04 v0.4.4
index:    3.42 s, 41250 files, 1830211 symbols, 12 processed (reused) (-8%)
memory:   peak working set 1480.20 MB (+3%), peak private 1390.55 MB, managed heap 910.40 MB

op             count             p50 ms             p95 ms             p99 ms            empty
completion      1000       4.10 (-12%)      18.20 (+2%)     40.31 (+25%!)     6.1% (=)
definition      1000        0.92 (+1%)       3.80 (-5%)       9.10 (+4%)    11.3% (-0.4pt)
references      1000      35.00 (+4%)     210.00 (+6%)     480.00 (+9%)     2.0% (=)
written:  D:\Work\MyGame\.vs\UEToVS\bench\bench.jsonl
```

- 括号内是和上一次相比的变化；超过 +10% 的耗时 / 内存，或空结果比例上升超过 1 个百分点，会带 `!`。
- `(reused)` 表示复用了已有索引，`(rebuilt)` 表示 `--reindex` 重建，`(new)` 表示第一次建索引。**索引耗时只有在 rebuilt / new 时才可比**。
- 空结果比例偏高的操作，可以加 `--details` 再看具体是哪些位置。

## 结果文件格式

`bench.jsonl` 每行一次运行，`event` 固定为 `bench.result`：

```json
{"event":"bench.result","timestampUtc":"2026-11-12T08:30:00.0000000Z","engineVersion":"0.4.5","project":"D:\\Work\\MyGame\\MyGame.uproject",
 "seed":1,"samples":1000,"reindexed":false,
 "index":{"ms":3420.0,"reused":true,"filesParsed":12,"files":41250,"symbols":1830211},
 "memory":{"peakWorkingSetMB":1480.2,"peakPrivateMB":1390.6,"managedHeapMB":910.4},
 "ops":{"completion":{"count":1000,"p50":4.1,"p95":18.2,"p99":40.31,"mean":6.2,"max":120.5,"empty":61,"errors":0,"emptyRatio":0.061}},
 "totalMs":52310.4}
```

`--details` 的每行是一个位置的一项操作：`{"op":"definition","file":"…","line":12,"col":8,"word":"Fire","ms":0.8,"results":1}`（行、列从 1 开始）。

引擎日志（`<解决方案>\.vs\UEToVS` 下的日志目录）里同时记录 `bench.start`、`bench.op`（每项操作的统计）和 `bench.result` 事件。

## 建议

- 对比两个版本时用相同的 `--seed` 和 `--samples`，先各跑一次热身（复用索引），再取第二次的结果。
- 测"冷启动"索引时间用 `--reindex`；它会删掉 C++ 索引，下次在 VS 中打开会使用新建的索引。
- 跑 bench 时关闭 VS（或至少关闭同一解决方案），避免两个引擎同时写同一份索引。
- 退出码：0 成功；参数错误、索引失败或被取消时非 0。
